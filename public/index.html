ZONE 04 // SHOP RULES & INCIDENT LOGS

How I build

Three rules from running small models and real bills, followed by the actual failure log from this repo.

PRINCIPLE 01

The AI reads. Code checks.

Models are good at reading messy things and bad at sums. So the model turns a photo into lines, and ordinary code decides what's wrong.

PRINCIPLE 02

Show the source.

An answer you can't check isn't worth much. Summaries link to the exact second in the video; bill checks show the line and the math.

PRINCIPLE 03

Write down what broke.

Every project keeps notes on what failed and why. The failures are usually the most useful part.

Field Incident Ledger — What Broke & How It Was Fixed

01 // What I Assumed

Vision LLMs could read a restaurant receipt, check the tax math, and draft a polite WhatsApp dispute in one prompt.

02 // How Real Data Broke It

Card payment rows printed below the total were subtracted as S$56.95 "errors", models guessed GST was included when it was added, and drafts invented numbers.

03 // The Deterministic Fix

Restricted item sums to rows above the subtotal, let printed totals decide tax mode in checks.ts, and built a {{placeholder}} verifier that rejects stray digits.
